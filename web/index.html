        The map
        
      
        
        
        drag
        pan
        
        
        wheel
        zoom, one level per notch
        
        
        click
        show how that render was made, in the info tab
          — which the click opens
        
        
        double-click
        the full original image, stitched from the
          lossless store rather than the archive's WebP. compare in its
          bar puts a second render beside it — side by side, or
          slider with the two superimposed under a divider you drag. The
          reference is the render you opened previously, or cell 0,0 if this is
          the first; the two scrollbars walk it along its row and down its
          column while the main image stays put
        
        
        arrows
        pan by a screenful's eighth, Leaflet's own step
        
        
        shift+arrows
        step exactly one render — the
          cell size comes from the map, so one press is one image at any zoom,
          tile size or block shape
        
      
        
      
        Zoom is bounded by what the archive holds — two levels
        below its shallowest, one above its deepest. If ⛰ build is
        marked stale, the pyramid is missing and zooming out is capped until
        you build it.
        

      
        Top bar
        
      
        
        
        map
        which archive; 1–9 switch. The view
          is kept, so two renderings of the same index stay comparable
        
        
        src
        store reads live from SQLite (a render appears the
          moment it is saved); archive reads the .pmtiles itself — what
          would be uploaded
        
        
        ⟳
        refetch everything visible without moving (r)
        
        
        ⛰ build
        build the zoom pyramid and re-serialize the archive.
          The picker beside it chooses how: scale averages four tiles into
          one — the classic pyramid — while sample stops averaging once a
          render would go under 64 px and takes a quarter of each of the four
          instead, so the shallow levels stay legible rather than turning to
          static. Building records the choice on the map
        
        
        ☰
        hide/show this panel (b)
        
      
        

      
        ⚙ config
        
      
        Everything the map draws and everything it does as renders land. These
        lived in the top bar until there were too many of them.
        
      
        
        
        tile grid
        outline every tile
        
        
        mark
        the marking overlay — see below (x)
        
        
        debug
        per tile: z/x/y, map zoom, size and corner
          lat/lng. The border says where the tile came from: blue stored, green
          upscaled from a shallower level, amber over-zoomed past the deepest
          (d)
        
        
        index
        row and column headers along the edges, the way a
          spreadsheet freezes them (i). The names are the renders'
          own tags — the two pickers under the box choose which tag names the
          rows and which the columns, and the map's own tags are what they
          offer. A header stays at the edge while any part of its row or column
          is on screen, and clicking it frames that row or column. A map that
          is not a table (one block per prompt, a lattice of models inside it)
          has no axis to name and says so
        
        
        freeze
        pins the first row and/or column of
          renders against the edge of the map — a spreadsheet's frozen panes,
          where index is its frozen headers. On a model × lora sweep
          that is each model with no LoRA and each LoRA on the base model: the
          baselines every other cell is read against, kept on screen next to
          whatever you are looking at. The strips scroll with the map and have
          no controls of their own. Each is one render thick, but never more
          than 256 px: zoom past that and the strip stops growing and shows the
          middle of the row or column instead, since two strips that kept pace
          with the zoom would leave no map between them. A drag that
          starts on a strip then scrolls that crop along the axis the
          strip froze — the row strip up and down, the column strip left and
          right — as far as its own render and no further. The map pans under
          it at the same time, exactly as a drag anywhere else would
        
        
        live
        refresh tiles as renders land; flash highlights
          each one as it changes
        
        
        follow new
        pan to each render as it lands — a long run can be
          watched without touching the mouse. Only the deepest level counts, so
          building the pyramid does not drag the view around; a render already
          fully on screen is outlined but does not move the map. Needs
          live
        
      
        

      
        info
        
      
        How the tile you clicked was made: prompt, seed, sampler, models, and
        the raw metadata under the fold. Clicking the map opens this tab;
        following a search result or a liked row does not, so a pass through a
        list stays on the list.
        
      
        
        
        copy
        the tile's z/x/y
        
        
        ⤢
        the full original image, same as double-clicking the map
        
        
        models
        the file each model was called in the graph. With a
          model catalogue on the box they link to where the model came from —
          Civitai or HuggingFace — under the model's own name, version, base and
          author. Matching is by sha256 where the tile recorded one, so a
          model renamed since the render still resolves and the row says what it
          is called now. No catalogue, no links: the names stay as they were
        
      
        

      
        search
        
      
        Title, tags and prompt; one result per render, not per tile.
        
      
        
        
        click a result
        frame that whole render
        
        
        hover
        outline it on the map
        
        
        /
        focus the box · Esc clears it
        
      
        

      
        liked
        
      
        Points of interest, kept in this browser.
        
      
        Hovering a render on the map puts a heart in its top-right
        corner — click it to like the render, click again to remove. It turns
        pink on hover to show what the click will do, and a liked render keeps
        its pink heart whether the cursor is there or not. The heart is hidden
        once a render is drawn smaller than one map tile, since below that it
        would cover the picture it marks.
        
      
        
        
        + tile
        save the tile selected on the map (s)
        
        
        drag a row
        reorder · double-click a name to rename ·
          × deletes
        
        
        copy / paste
        the whole list as JSON, to move it between
          browsers
        
        
        ↗ / ⇄
        the target is off screen / in another archive, which is
          why hovering it seems to do nothing
        
      
        

      
        marks
        
      
        Triage: approve what you want, reject the rest. Turn mark on
        first (x).
        
      
        
        
        shiftaltctrl
        
        
        dragapprove a rectanglereject itdeselect
        
        
        clickthe same, on the whole render under the
          cursor
        
      
        
      
        Approved renders get a green outline and nothing painted
        over them; rejected ones are dimmed so they recede. Esc clears
        every mark.
        
      
        
        
        add
        save the current marks as a named set; click a set to
          load it back, double-click to rename
        
        
        clear
        clear the map's marks — saved sets are untouched
        
        
        reject rest
        reject every tile that holds a render and
          is not marked yet: the last step of a pass
        
        
        copy
        the current marks as JSON
        
        
        mark by search
        approve or reject everything a query matches,
          whole renders at a time
        
      
        
      
        Sets live in this browser. A set remembers the zoom it was
        made at and will not load onto a map that marks at a different
        granularity.
